smoking-status flag surface (requested by a real GP user) · **Surfaces
rendered:** Sentinel panel module, real rules engine + shipped rules, recorded
(ex-smoker, Nov 2025) and not-recorded states, light/dark/colourblind, 420px.

> **This panel is synthetic.** Every reaction below is a persona simulation —
> a structured heuristic for surfacing UX problems cheaply. It is NOT user
> research and no quote below is from a real clinician. The triggering request
> ("can we get a smoking status flag?") is real; everything else is a model.

## Verdict

Before this change the suite technically *showed* smoking status — buried in
small grey caption text inside up to three duplicated SMOK002 QOF cards, three
screens down, styled as a payment-recording task. Every persona failed or
nearly failed the "does she smoke?" five-second test, and the absent state
(quiet grey "NO DATA") was unanimously judged worse than the recorded state.
The panel converged decisively on **one authoritative, neutral, dated line in
the "Monitoring for" patient card** — shipped in v3.174.0.

## Ruling (practice lead)

**Adopted — built as v3.174.0** (`shared/smoking-status.js`, snapshot field
`smoking`, banner line in `side-panel/modules/sentinel/sentinel.js`):

- **Placement:** one line in the `Monitoring for` patient card (4/7 first
  choice incl. the technophobe floor and the domain expert). The card already
  carries patient facts (NHS/DOB/age/sex), answering the "identity chrome"
  objection. A separate chip card was rejected: it steals list space from
  needs-action chips (Pellew) and duplicates the fact (Hollis).
- **Content:** `Smoking: <bucket> · <Mon YYYY> (<N> mo ago)`; bucket is
  conservative (current/ex/never only on unambiguous terms; otherwise
  "unclear — see record"); verbatim coded term + exact date + window caveat in
  the tooltip; `multiple entries` marker when visible entries disagree.
- **Absence:** `Smoking: no entry in the last 13 months — check record` —
  bounded to the extension's real data window (journal augment ≈400 days);
  never "not recorded", never "NO DATA" (unanimous).
- **Colour:** neutral always, in both states (6/7; see judgement call below).
  The word carries the state — survives colourblind mode by construction.
- Pinned by `test-smoking-status.js` (44 assertions).

**Adapted:**
- Eileen's "make absence LOUD": overruled for the flag itself — clinical-alarm
  salience stays reserved for needs-action signals (suite constraint;
  Hollis/Patel argued the same). Recording-currency urgency remains the QOF
  SMOK002 chip's job. *Reverse with: colour `.sent-patient-smoking` amber on
  the absent state — one CSS rule — after CSO review.*

**Recorded as follow-ups, not built (out of the scoped question):**
1. **SMOK002 triplication** — one fact renders as up to 3 near-identical QOF
   cards (one per register), inflating the Brief's red count (6/7 personas).
   Touches QOF chip machinery; needs its own change + CSO eyes.
2. **Brief inversion** — "recorded but QOF-lapsed" shouts red while "never
   recorded" sits quiet grey (Nair/Cobb/Hollis). Existing suite-wide QOF
   no_data semantics; a deliberate review, not a freehand tweak.
3. **Echoes on Record tab / SMR pack / in-page HUD** (Hollis/Patel D-votes) —
   S-size each once the one authoritative derivation exists (it now does).
4. **Truncated Brief lines** (mid-word, no ellipsis — Nair): cosmetic, panel
   shell.
