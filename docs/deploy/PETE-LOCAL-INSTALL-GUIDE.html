Medicus Suite — setup guide for Pete

Local install on each PC. Shared folder is only the drop-box. Microsoft Edge (NHS default). One practice packager + first end-user PC. September 2026.

1. What this solves

Running Suite from the shared drive is slow, and staff hate clicking Reload unpacked after every update. The fix: each PC keeps a copy on its own disk. You drop a new version in the shared folder. A small Windows task copies it across at logon. Suite then shows Suite files updated — Reload. The extension never copies files itself and never installs itself from the share.

2. Pete — publish a new Suite version

Use your real share path everywhere you see S:\MedicusSuite (or \\Server\MedicusSuite). Create incoming and current once. Always publish into current — never a folder named after the version.

  1. Unpack the new zip into S:\MedicusSuite\incoming. You should see manifest.json in that folder, not inside another folder.
  2. Copy tools\windows\suite-release.example.json from the zip to S:\MedicusSuite\incoming\suite-release.json.
  3. Open suite-release.json in Notepad. Set "version" to the same number as in manifest.json (for example 3.261.16). Set "ready" to false while you are still copying. Leave "allowDowngrade" as false.
  4. When every file is in place, change "ready" to true and save.
  5. Swap the folders: rename current to current-old, rename incoming to current, then make a new empty incoming for next time. Delete current-old when you are happy.
  6. Do not ask anyone to Load unpacked from the share.

3. First PC — one-time setup

Put the two scripts from the zip on the share (for example S:\MedicusSuite\tools\windows\). PowerShell is fine. Do this on one machine first and check it works before rolling out.

  1. Close Edge (and Chrome if it is open) on this PC.
  2. Right-click Start → Windows PowerShell. Type these two lines (change the share path if needed) and press Enter after each. That creates a logon task named MedicusSuite-LocalSync. cd S:\MedicusSuite\tools\windows powershell -NoProfile -ExecutionPolicy Bypass -File .\Register-SyncTask.ps1 -Reference "S:\MedicusSuite\current"
  3. In the same window, run the copy once now so the local folder exists before you open Edge. You want %LOCALAPPDATA%\MedicusSuite\extension containing manifest.json. powershell -NoProfile -ExecutionPolicy Bypass -File .\Sync-MedicusSuite.ps1 -Reference "S:\MedicusSuite\current"
  4. Open Edge. Type edge://extensions in the address bar and press Enter.
  5. Turn on Developer mode (top right). Click Load unpacked. In File Explorer’s address bar paste %LOCALAPPDATA%\MedicusSuite\extension, then Select Folder.
  6. On the Suite card click Details. Source / Loaded from must be that local path — not a path starting with \\ and not S:\.
  7. Pin the Suite icon. Open Options once. Repeat steps 1–6 on each other PC. Never Load unpacked from a different folder later — that makes Suite forget its settings.

4. What users see after you publish

Next logon (Edge closed) the PC copies the new files. Users see Suite files updated — Reload in Options and at the top of the side panel. They click Reload. They do not open edge://extensions and they do not download a GitHub zip.

5. If it does not copy or does not update

What you see What to do
Share is down / laptop at home Leave it. The last local copy keeps working. The task tries again next logon.
Edge (or Chrome) is still open The copy will not replace the live folder (avoids a half-updated Suite). Close the browser and run the Sync script again, or wait for the next logon.
ready is still false You have not finished publishing. PCs will not copy. Set it to true and swap to current.
Details shows the share, not the local folder This PC is on the old slow setup. Remove the extension and Load unpacked again from %LOCALAPPDATA%\MedicusSuite\extension.
No Reload banner Same version already, share down, Edge was open at logon, or ready was false. Check the local manifest.json version against yours.
Suite “forgot” everyone Someone loaded a different folder. Load unpacked from the original local path again.

6. What this is not

Practice Profile is settings, not a new Suite version. Options → Backup & Restore → Practice Profile pushes practice rules and defaults. It does not copy extension files. A new zip is bits: you publish to the share, Windows copies, users click Reload. Do not mix the two. Do not use the GitHub “View release” banner for practice machines.
